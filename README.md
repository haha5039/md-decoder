# 마스터듀얼 카드 디코더

[배포된 사이트](https://haha5039.github.io/md-decoder/) · 카드 디코더 이벤트의 공개 정보와 O/X 판정으로 후보를 좁히고 다음 제출을 추천하는 웹 도구입니다.

## 사용법

추천 카드와 후보 카드는 같은 너비와 프레임·속성·레벨/랭크/링크·종족·공격력·수비력 표시를 사용합니다.

1. 게임에서 공개된 값을 **정답 카드 확실한 정보**에 입력하고 **힌트 기록**을 누릅니다. 새 문제의 최초 공개 항목 1개는 무료이며, 추가 공개 항목마다 힌트 1회가 차감됩니다. 여러 항목을 함께 기록해도 항목별로 계산합니다. 효과와 효과/펜듈럼처럼 복합 프레임을 정확히 구분하세요.
2. 제출한 카드를 검색하고 6개 항목 모두 같은 **O / X** 순서로 판정을 기록합니다. 프레임이 처음 맞았을 때만 아래에 **펜듈럼 O / X**가 나타나며 기본값은 X입니다. 펜듈럼 O를 고르면 제출 카드·현재 단서·다른 판정과 맞는 공개 프레임만 선택할 수 있습니다. 종류가 하나뿐이면 자동으로 선택하며, 프레임을 기록했거나 초기 힌트에서 정확한 프레임을 입력한 뒤에는 추가 질문을 반복하지 않습니다. 일치한 레벨은 기존과 같이 제출 카드의 룰상 값을 반영합니다.
3. **다음 카드 추천**으로 추천을 확인합니다. 남은 도전이 1회면 즉시 정답 확률, 2회면 가능한 경우 2회 내 성공률, 3회 이상이면 작은 후보군에서 3~4회 탐색을 사용합니다. 후보가 많으면 정보량·평균 잔여를 비교합니다. 수동 기준은 항상 표시됩니다. 현재 결과의 정렬 기준을 직접 바꿀 수 있으며, **다음 카드 추천**을 다시 누르면 자동 기준으로 재계산합니다.
4. 잘못된 입력은 **되돌리기** 또는 단서 옆 삭제 버튼으로 해당 입력 묶음을 취소합니다. 실제로 차감한 도전·힌트만 환급합니다.
5. 정답을 맞힌 뒤 **다음 문제**를 누르면 남은 도전·힌트를 유지하고 남은 문제 수만 줄여 새 추론을 시작합니다.

남은 도전이나 힌트가 0회여도 정보를 기록하고 후보·추천을 계속 계산할 수 있습니다. 잔여 수는 0 아래로 내려가지 않으며, 실제로 차감하지 않은 횟수는 되돌릴 때 환급하지 않습니다. 추론 내용과 남은 횟수는 이 브라우저에 자동 저장됩니다. 구버전의 자동 프레임 확정 값은 복원 시 제거하고 실제 입력한 공개 값은 유지합니다. 과거 O 기록에 공개 프레임을 추가하는 경우 힌트는 차감하지 않습니다. 초기화하면 기본값(도전 4, 힌트 1)으로 돌아갑니다. 후보 목록은 기본 60장을 표시하며 60장씩 더 볼 수 있습니다. 상단에서 한국어·영어와 라이트·다크 모드를 전환할 수 있으며 설정은 브라우저에 저장됩니다.

## 이벤트 규칙과 데이터

- 프레임, 속성, 레벨/랭크/링크, 종족, 공격력, 수비력을 비교합니다.
- 도전 판정에서는 펜듈럼 프레임 중 한 부분만 겹쳐도 일치합니다. 프레임 O만으로 제출 카드와 정답 카드의 전체 프레임이 같다고 단정하지 않습니다. 게임에 공개된 실제 프레임을 같은 판정 입력에서 기록하며, 후보 필터는 그 정확한 값을 사용합니다. 이 기록은 별도 힌트를 소비하지 않습니다.
- 촐킨·비시바르킨·FNo.0/SNo.0 계열은 인쇄 수치와 룰상 수치 모두로 판정하고, 룰상 수치를 공개합니다.
- 정답 인정에는 전체 프레임을 포함한 6항목의 값이 모두 같아야 합니다. 이름이 달라도 6항목이 동일하면 정답입니다. 펜듈럼의 일부만 겹치는 것은 프레임 힌트를 공개하는 O 판정이며, 전체 프레임이 다른 카드까지 정답이 되지는 않습니다. 한 번 제출한 카드는 다시 차감하지 않습니다.
- `?`는 미정 공격력/수비력(-1), `없음`은 링크 몬스터 등의 수비력 부재(null)로 구분합니다.

2026-09-28 기준 데이터는 인게임과 동일하게 몬스터 **9,058장**, 순수 효과 프레임 **5,796장**, 땅 속성 **2,047장**, 야수전사족 **261장**입니다. 동명인 카오스 솔저 일반·의식 몬스터는 별도 카드로 유지합니다.

카드 포함 여부·한국어명·이벤트 판정에 쓰이는 6개 스테이터스는 [YAML Yugi의 Master Duel 데이터](https://github.com/DawnbrandBots/yaml-yugi)를 기준으로 하고, 카드 ID와 이미지는 [YGOPRODeck 전체 API](https://ygoprodeck.com/api-guide/)에서 결합합니다. 카드 디코더에서 제외되는 콜라보 캠페인 카드는 출시 메타데이터로 판별합니다. 특정 카드 ID를 영구 블랙리스트 처리하지 않으므로 실제 게임이나 데이터 분류가 바뀌면 다음 갱신에 자동 반영됩니다. 데이터 출처가 비어 있거나 결합되지 않은 카드가 있으면 기존 데이터를 유지합니다.

GitHub Pages는 매일 데이터 생성 작업을 실행합니다. 사용자는 설정의 **최신 데이터 받기**를 눌러 마지막으로 검증·배포된 데이터로 브라우저 캐시를 갱신할 수 있습니다. YAML Yugi 데이터는 AGPL-3.0 조건으로 제공됩니다.

플레이 모드는 **횟수 제한 없는 연습 모드**입니다. 일일 지급·보너스 힌트 발동·보상은 재현하지 않습니다.

## 추천 알고리즘

모든 후보가 같은 확률로 정답이라고 가정합니다. 추천 계산과 후보 갱신은 화면에 입력한 프레임 결과와 나머지 5개 항목의 O/X를 사용하며, 성공은 하나의 종료 결과로 처리합니다. 프레임이 일치하는 실패 결과는 게임에 공개되는 정답의 전체 프레임까지 구분합니다.

| 지표 | 의미 |
|---|---|
| 기대 정보량 | 공개 결과별 후보 분포의 Shannon entropy 최대화 |
| 최악 잔여 최소 | 실패 시 최대 잔여 후보 수 최소화 |
| 평균 잔여 최소 | 결과별 후보 수 제곱 합 / 전체 후보 수 최소화; 성공은 잔여 0 |
| 즉시 정답 확률 | 이번 제출로 6항목 모두 일치하는 후보의 비중 |
| 2회 내 성공 확률 | 첫 제출 성공 + 실패 결과별 최선의 다음 제출 성공; 서로 구분되는 후보 유형 60개 이하에서 전수 계산 |
| 3~4회 내 성공 확률 | 유형 30개 이하는 3회, 16개 이하는 4회 탐색; 같은 성공률이면 기대 도전 소비가 적은 선택을 우선 |

2회 내 확률은 추가 유료·보너스 힌트를 쓰지 않는 조건입니다. 힌트 추천은 미공개 항목이 같은 확률로 선택된다고 가정하고, 각 공개 결과에서 다시 고를 수 있는 최선의 카드까지 계산합니다. 서로 다른 후보 유형이 12개 이하면 지금 힌트를 쓰는 선택과 추천 카드로 먼저 판정한 뒤 결과별로 힌트를 쓰거나 보존하는 선택을 비교합니다. 남은 도전 내 성공률과 도전·힌트 소비를 함께 평가합니다. 더 큰 초기 후보군은 단기 추정만 가능하므로 첫 판정의 정보를 우선합니다. 마지막 도전이나 충분히 큰 계산상 이득 등에서는 먼저 힌트를 쓸 수 있습니다. 첫 판정 이후에는 입력한 자원에 맞춰 재평가합니다. 힌트가 도전의 1/4만 지급되는 점을 반영해 도전이 0회면 보존하고, 남은 문제 대비 힌트가 적거나 도전이 넉넉할수록 사용 기준을 높입니다. 사용자가 입력한 자원만 사용하며 기간 입력이나 자동 지급을 추가하지 않습니다. 도전도 문제별로 기계적으로 나누지 않고 매 입력마다 재평가합니다. 사용 판단과 계산 근거는 하나의 힌트 안내에 표시하며, 여러 회의 성공률과 한 번의 성공률 추정을 구분합니다. 엔트로피나 평균 잔여 최소가 전체 해결 횟수의 최적성을 보장하지는 않습니다.

깊은 탐색의 서로 다른 선택지가 96개 이하면 전수 계산합니다. 그보다 복잡하면 정보량·평균 잔여·최악 잔여·즉시/2회 성공률 각 상위 12개 선택지의 합집합을 탐색하고 결과에 **추정**을 표시합니다. 1회·2회 계산은 전수 계산을 유지합니다.

동일한 판정·공개 결과를 만드는 카드의 계산을 공유하면서 카드 수 가중치를 유지합니다. 펜듈럼의 부분 일치를 동치관계로 취급하지 않습니다. 프레임·레벨을 비트마스크로 전처리하고 Web Worker에서 계산해 화면 입력을 막지 않습니다. 후보가 변경되면 진행 중인 계산을 취소합니다. 정답 추천에는 정답 후보와 6항목의 값이 모두 같은 카드만 포함하며, 일부 프레임만 겹치는 카드는 정보 수집용으로 평가합니다. 공개 프레임이 싱크로/펜듈럼이면 정답 후보와 정답 추천은 모두 싱크로/펜듈럼으로 제한됩니다.

## 개발 및 검증

Node.js 22.12 이상을 권장합니다.

```bash
npm install
npm run dev
npm test
npm run build
npm run evaluate -- 50 4
npm run compare -- 50 4
npm run data:update
```

기본 접속 주소: [http://localhost:5173/md-decoder/](http://localhost:5173/md-decoder/). 개발 서버는 모든 네트워크 인터페이스에서 수신합니다. 같은 네트워크의 다른 기기에서는 서버 컴퓨터의 LAN IP와 포트 5173으로 접속하세요.

프로젝트를 수정한 뒤에는 개발 서버를 다시 시작하고 접속 여부를 확인합니다. GitHub Actions에서도 테스트 성공 후 빌드합니다.

`src/utils.js`의 공통 판정, `src/solver.js`의 추천 엔진을 도우미·플레이·시뮬레이션이 공유합니다. 시뮬레이션은 고정 시드와 동일한 정답/초기 힌트로 각 전략을 비교하고, 최대 8회에서 종료합니다. 실패를 성공 평균에 섞지 않고 실패 수, 정답 제거 여부, 2·3·4회 내 성공률, 성공 사례 평균·95백분위 횟수, 계산 시간을 보고합니다. 표본이 적은 결과를 전체 이벤트 성능으로 해석하지 마세요.

순수 함수 회귀 테스트는 프레임 수치, 특수 레벨, 공개 정보 반영, 즉시/2~4회 성공률, 힌트의 성공률과 도전 절약량, 최초 무료·유료·보너스 힌트 기록, 중복 프로필 가중치, 선택지 순서, 다국어 카드명, 데이터 검증 및 자원 환급을 검사합니다.

개인 연구용 비공식 도구이며 코나미와 무관합니다.
